# Decisions

- 2026-11-26: Docs are global in `docs/` in three sets: `technical/<project>/{vision,architecture}` (internal, MkDocs; vision = product vision and goals, architecture = arc42 + ADRs), `user/` (end user, MkDocs, served on the Raspberry Pi via `docs/Dockerfile.user`), `llm-wiki/` (agent knowledge base). Promote settled wiki knowledge into technical/user. Wiki: /concepts/documentation-structure.md.
- 2026-11-26: NO application scaffolding yet: the software architecture is still open. The repo only has the wiki, agents/skills, lint/format config and CI. Code projects are created later by the user's agents from what the wiki says. A first scaffold (Litestar/Polars/DuckDB backend with simulator) was generated and deliberately discarded.
- 2026-11-26: Bench type is generic and open: inertia dynamometer (Trägheitsprüfstand), roller dynamometer (Rollenprüfstand), possibly with a brake/load unit. The wiki models a generic "dynamometer test bench" with variants; no code or folder is named after one type. Requirement (not architecture): simulation mode so development works without hardware. Wiki: /entities/dynamometer-test-bench.md.
- 2026-11-26: Wiki lives in `docs/llm-wiki/` (own bundle root `wiki/`), but agents and skills live in repo-root `.github/` because Copilot only discovers them at the git root. Agents say "base path docs/llm-wiki".
- 2026-11-26: Monorepo conventions (tooling only): Python = ruff (+ pytest, uv), TypeScript = prettier + eslint, C++ = clang-format, Markdown = markdownlint, Docker = hadolint, shared `.editorconfig`, pre-commit, per-project CI with path filters. Wiki: /concepts/monorepo-conventions.md.
- 2026-11-26: Wiki conventions carried over from the author's earlier OKF wiki: OKF v0.2, English wiki / original-language raw, LLM pages `status: draft`, only the human verifies, raw immutable, learning backlog, four personas, memory protocol.
